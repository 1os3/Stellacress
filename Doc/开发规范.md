## 1. 技术基线

- 使用 **Godot 4.x**；确切版本以 `project.godot` 和团队约定为准，未经评估不得自行升级引擎版本。
- 默认使用 **GDScript 2.0**。只有经性能分析证明 GDScript 无法满足目标时，才引入 C#、GDExtension 或原生模块。
- 项目内路径统一写为 `res://...`，用户存档和运行时缓存统一写入 `user://...`。
- 源文件、配置文件与文档统一使用 UTF-8 和 LF 换行。
- 游戏逻辑不得依赖编辑器插件才能在导出版本中运行。

## 2. 核心原则

| 原则 | 要求 |
| --- | --- |
| 数据与表现分离 | 遗传、育种、表型、谱系和存档属于纯数据/服务层；UI 与场景只负责输入和展示。 |
| 规则驱动 | 基因、QTL、环境和创始品系由 Resource/数据文件定义，不把平衡参数散落在脚本中。 |
| 确定性优先 | 相同定义版本、存档状态和种子必须产生相同的遗传结果。 |
| 组合优于继承 | 优先用小场景、小组件和服务组合功能，避免深层 Node/脚本继承树。 |
| 明确所有权 | 每份可变数据只能有一个权威写入者；其他对象通过公开接口或信号读取变化。 |
| 可测优先 | 核心算法不得依赖场景树、帧率或全局随机状态，必须能独立运行自动化测试。 |
| 性能以证据为准 | 先保持实现清晰，再用 Profiler 和基准测试定位瓶颈；不得凭感觉提前复杂化。 |

## 3. 工程目录与职责

新项目按以下结构组织；目录可随功能逐步创建，不建立空目录：

```text
res://
├── autoload/                 # 少量全局生命周期协调器
├── genetics/
│   ├── definitions/          # 物种、染色体、位点、性状等 Resource 类
│   ├── runtime/              # Genome、Haplotype、Segment、PlantRecord 等数据类
│   └── engines/              # 减数分裂、遗传、表型、育种、谱系、筛选算法
├── storage/                  # PlantStore、GenomeStore、SaveService
├── gameplay/                 # 游戏流程、任务、经济与研究系统
├── ui/
│   ├── components/           # 可复用 UI 组件
│   ├── screens/              # 完整页面/界面
│   └── themes/               # Theme、字体和通用样式
├── scenes/                   # 世界、主流程及非 UI 场景
├── data/
│   ├── species/              # Stellacress 物种与位点数据
│   ├── founders/             # 创始品系
│   └── environments/         # 环境定义
├── assets/
│   ├── art/
│   ├── audio/
│   └── fonts/
├── tests/                    # 与源码结构对应的自动化测试
└── devtools/                 # 仅开发期使用的导入、验证和基准工具
```

目录规则：

- 文件按职责归属，不按文件类型堆放；例如遗传引擎脚本不得放入 `scripts/` 大杂烩目录。
- 领域代码不得反向依赖 `ui/`、具体关卡或场景。
- `autoload/` 只放确实需要跨场景存活且具有唯一实例的对象。工具函数、常量集合和普通服务不得因为调用方便而设为 Autoload。
- 第三方插件只放在 `res://addons/<plugin_name>/`，项目代码不得混入插件目录。
- 测试目录尽量镜像源码目录，例如 `genetics/engines/meiosis_engine.gd` 对应 `tests/genetics/engines/test_meiosis_engine.gd`。

## 4. 命名与 GDScript 风格

遵循 Godot/GDScript 官方风格，并采用以下项目约定：

| 对象 | 命名 | 示例 |
| --- | --- | --- |
| 文件、目录 | `snake_case` | `meiosis_engine.gd` |
| 变量、函数、信号 | `snake_case` | `make_gamete()`、`plant_selected` |
| 类与 `class_name` | `PascalCase` | `MeiosisEngine` |
| 常量、枚举成员 | `UPPER_SNAKE_CASE` | `MAX_CHROMOSOME_COUNT` |
| 私有成员 | 前缀 `_` | `_segment_cache`、`_validate_genome()` |
| 场景节点名称 | `PascalCase` | `CandidateList` |
| Resource 文件 | `snake_case.tres` | `stellacress_species.tres` |

代码要求：

- 为成员变量、参数、返回值和非显然的局部变量写静态类型。
- 使用 `class_name` 的类型可直接引用；不要为了省一行代码滥用 `preload()`。
- 一个脚本只承担一个清晰职责；公共类通常独占一个同名文件。
- 优先早返回，避免超过三层的条件嵌套。
- 函数应保持短小；超过约 40 行时检查是否混合了校验、转换、计算和展示等职责。算法本身不可合理拆分时不强行拆分。
- 不使用魔法数字或魔法字符串。领域参数进入定义资源；真正固定的不变量使用具名常量。
- 使用 `StringName` 表示频繁比较的稳定 ID，使用 `enum` 表示封闭状态集合。
- 对数组和字典使用具体类型，例如 `Array[Segment]`；确实需要异构数据时才使用无类型容器。
- 仅为有语义的参数使用默认值；不得用默认参数偷偷复制平衡配置。

```gdscript
class_name MeiosisEngine
extends RefCounted

const CENTIMORGANS_PER_MORGAN: float = 100.0

func make_gamete(
        genome: Genome,
        species: SpeciesDefinition,
        rng: RandomNumberGenerator,
) -> Gamete:
    _validate_genome(genome, species)
    return _build_gamete(genome, species, rng)
```

## 5. 场景、节点与脚本

- Node 只用于需要场景树生命周期、输入、渲染、物理、音频或 UI 布局的对象。
- `PlantRecord`、`Genome`、`Haplotype`、`Segment`、候选评分等模拟数据使用 `RefCounted`、Resource 或紧凑数据结构，**不得每株植物创建一个 Node**。
- 批量生成 5,000 株后代时，UI 只实例化当前可见的少量控件，并使用列表虚拟化、分页或候选压缩。
- 场景根节点名称与场景文件职责一致；可复用场景对外暴露最少必要接口。
- 不使用脆弱的多层 `get_parent()`、绝对节点链或随处调用 `get_node()` 建立依赖。使用导出引用、唯一名称、构造/初始化参数或信号。
- `_process()` 和 `_physics_process()` 默认不启用。只有确实需要逐帧更新的节点才实现，并在不需要时关闭处理。
- 模拟结果不得依赖 FPS、动画时长、节点遍历顺序或 UI 打开顺序。
- UI 脚本不得直接修改 Genome、存档表或定义 Resource；必须调用对应服务。

## 6. 数据定义与配置

### 6.1 数据分类

| 类型 | 示例 | 规则 |
| --- | --- | --- |
| 不可变定义 | 染色体长度、位点位置、基因效应、环境参数 | 使用自定义 Resource 或可校验的数据文件，运行期只读。 |
| 运行时状态 | 植物、基因组、育种事件、试验结果 | 由 Store/Service 持有，不写回定义资源。 |
| 用户设置 | 音量、语言、显示选项 | 独立保存，不混入游戏存档或物种定义。 |
| 固定不变量 | cM 到 Morgan 的换算、无父母 ID | 使用具名常量。 |

### 6.2 定义资源

- `SpeciesDefinition` 是物种数据入口，引用染色体、位点、性状、上位性规则和创始品系定义。
- 所有可调平衡值必须在 `data/` 下的定义资源中有唯一来源；实现脚本只读取，不提供第二份“兜底默认值”。
- Resource 的导出字段必须声明类型、单位和有效范围。坐标字段名称必须带单位，如 `position_cm`、`length_cm`。
- 运行时不得修改从磁盘加载的共享定义 Resource。确需临时变体时先 `duplicate(true)`，并明确其所有者。
- 定义之间使用稳定 ID 建立关系，不依赖数组当前顺序、显示名或本地化文本。
- 数据加载后统一执行交叉引用和不变量校验；发现错误应尽早失败并指出资源路径与字段。

### 6.3 资源 ID

- 位点、性状、环境、创始品系和事件类型都必须有不随显示名称变化的稳定 ID。
- ID 一旦进入正式存档不得复用或改变含义。弃用项保留迁移映射。
- 面向玩家的名称使用本地化键，不作为业务逻辑判断条件。

## 7. 遗传模拟约束

`Stellacress_Genetics_Technical_Design.md` 定义遗传模型。实现必须保持以下边界：

- 自交、杂交和回交统一建立在“独立生成两个配子”之上，不按世代标签硬编码概率。
- 染色体重组使用遗传坐标；核心算法不得混用 cM、Morgan 与物理坐标。
- 后代基因组使用“创始单倍型 + 祖源 Segment + 稀疏 Variant”表达，不复制虚构的完整 DNA 序列。
- 主效基因、QTL、显性、上位性、环境响应和 G×E 由定义数据驱动；引擎不得按具体基因代码堆叠特判。
- `PlantRecord`、Genome、事件和表型摘要分离存储。Genome 是遗传事实源，事件日志不能替代 Genome。
- F1、F2、BC1 等仅为 UI/谱系标签，不参与遗传计算。
- 表型计算明确区分遗传潜力、环境实现值和观测噪声。

每次创建或加载基因组都必须保证：

1. 每条 Haplotype 至少有一个 Segment，首段 `start_cm == 0.0`。
2. `Segment.start_cm` 严格递增且位于染色体范围内。
3. 相邻 Segment 的 `founder_haplotype_id` 不相同。
4. Variant 位于染色体范围内并保持稳定排序。
5. 二倍体的每条染色体恰好有两个同源副本。
6. `plant_id` 永不复用；非创始个体的父母 ID 必须指向已有记录。

## 8. 随机数与可重现性

- 禁止核心模拟使用全局 `randf()`、`randi()`、`randomize()` 或共享的可变 RNG。
- 随机函数必须显式接收 `RandomNumberGenerator` 或稳定种子。
- 每个育种事件按 `run_seed + event_id + offspring_index + stream_id` 派生独立随机流。
- 配子 A、配子 B、突变、环境噪声使用不同 `stream_id`，不得靠调用先后共享一个随机序列。
- 调整 UI、日志或批处理顺序不得改变模拟结果。
- 若 PRNG 或种子散列算法发生变化，必须提升 `prng_algorithm_version` 并提供存档兼容说明。
- 自动化测试必须覆盖保存/读取前后以及分批/整批执行的一致性。

## 9. 信号、服务与依赖

- 信号用于通知“已经发生的事件”，命名使用过去式或结果语义，例如 `breeding_completed`、`save_failed`。
- 命令调用使用普通方法，不把“请求执行操作”伪装成广播信号。
- 信号参数必须携带订阅者真正需要的稳定 ID 或只读结果，避免订阅者再次遍历全局状态猜测变化内容。
- 连接和断开信号的生命周期必须对称；动态创建的订阅者退出时不得留下悬空连接。
- 引擎类保持无状态或显式持有状态，优先使用可直接实例化测试的 `RefCounted`。
- Store 是对应数据的唯一权威写入者；Service 负责编排规则，UI 只调用 Service 并订阅结果。
- 避免循环依赖。允许的主要依赖方向为：

```text
UI / Gameplay -> Services / Engines -> Runtime Data / Definitions
                               \----> Storage interfaces
```

- Autoload 负责应用级协调、场景切换或全局服务装配，不承载庞大的领域算法。

## 10. 存档与兼容性

- 长期存档不得直接序列化 Node 树或 Godot 对象引用图。
- 存档至少记录 `save_format_version`、`species_definition_version`、`prng_algorithm_version`、`run_seed` 和 ID 分配状态。
- 正式进入存档的数据结构变更必须提供迁移函数，或明确拒绝旧版本并给出可理解错误；不得静默误读。
- 保存时先写临时文件，完整校验成功后再替换正式存档，避免中断产生半份存档。
- 加载外部数据时按不可信输入处理：校验版本、长度、偏移、ID 引用和数值范围。
- `plant_id`、`event_id` 等持久化 ID 单调分配且永不复用。
- 历史记录可压缩或分块按需加载，但不得破坏父母关系、祖源来源和关键事件的可追溯性。

## 11. 错误处理与校验

- 对编辑器或数据作者造成的定义错误，在加载阶段立即报告，错误信息包含资源、字段、实际值与期望条件。
- 对玩家可恢复的运行时失败返回明确结果，并由 UI 展示可理解提示；不要用 `assert` 处理玩家输入或 I/O 失败。
- `assert` 只用于程序员错误和内部不变量，不能承载导出版本必须执行的业务逻辑。
- 公共入口校验一次，内部可信函数不重复堆叠同一校验。
- 不吞掉错误。捕获或转换错误时保留足以定位问题的上下文。
- `push_warning()` 用于可继续运行但值得修复的问题，`push_error()` 用于当前操作不能正确完成的问题。
- 不为理论上不可能出现的状态编写大量静默兜底；暴露并修复不变量破坏。

## 12. 测试规范

### 12.1 测试分层

| 类型 | 范围 | 要求 |
| --- | --- | --- |
| 单元测试 | Segment、等位基因查询、QTL effect、筛选函数 | 快速、无场景树依赖、固定输入输出。 |
| 统计测试 | 孟德尔分离、重组率、噪声分布 | 固定种子、足够样本量、明确统计容差。 |
| 集成测试 | cross/self、存档往返、定义加载 | 验证服务和数据层协作。 |
| 场景测试 | 关键 UI 与流程 | 只覆盖必须依赖场景树的行为。 |
| 性能基准 | 大群体生成、谱系查询、存档读取 | 记录环境、规模和基线，避免只看单次耗时。 |

### 12.2 强制回归项

- `AA × aa` 在突变关闭时产生 100% `Aa`。
- `Aa` 自交的大样本比例接近 `1:2:1`。
- 相距 6 cM 的位点在规定模型下重组率接近理论值。
- 不同染色体位点独立分配。
- Segment 无空洞、无重叠且相邻同祖源片段已合并。
- 任意个体的祖源比例之和为 `1 ± 浮点容差`。
- 相同种子合同生成字节级或字段级相同的 Genome。
- 存档往返后继续模拟得到相同结果。
- 同一基因型在定义的不同环境中表现出预期 G×E 方向。

测试约定：

- 测试名描述行为和期望，不使用 `test_1`、`test_misc`。
- 浮点比较统一使用项目定义的容差，不直接比较计算结果是否完全相等。
- 统计测试必须固定种子，容差基于样本量和理论分布；不得用放宽阈值掩盖失败。
- 修复缺陷时先添加能复现问题的测试，再修复实现。

## 13. 性能规范

- 性能优化必须附带 Profiler、Monitor 或可重复基准的证据。
- 热路径避免为每个位点、Segment 或个体创建临时 Dictionary、闭包和短命对象。
- MVP 可使用类型化 `Array` 和 `RefCounted`；规模达到瓶颈后再迁移至 `PackedInt32Array`、`PackedFloat32Array` 或版本化二进制块。
- 每次重组后立即合并相邻同祖源 Segment，并去除量化后重复的交叉点。
- 大批量计算不得在主线程上每处理一个个体就刷新 UI。按批次计算并限制进度更新频率。
- 若使用线程或 WorkerThreadPool：
  - 工作线程不访问场景树和非线程安全的 Resource；
  - 输入为不可变快照，输出在主线程统一提交；
  - 每个后代的 RNG 由稳定索引派生，结果不得依赖任务调度顺序。
- 第一阶段性能目标以设计文档为准：5,000 株群体不创建 5,000 个 Node，50,000 次配子生成内存稳定，100,000 条谱系父母索引可查询。

## 14. 注释与文档

- 注释和项目文档使用中文；代码标识符使用英文。领域术语首次出现时可附英文。
- 注释解释设计原因、不变量、单位和非显然取舍，不复述代码。
- 公开类、复杂算法和容易误用的公共方法使用 `##` 文档注释。
- 数学实现必须注明模型名称、单位、输入范围和参考公式；例如明确 Haldane 模型的输入距离为 Morgan。
- TODO 统一为 `# TODO(负责人或议题): 内容`；无人负责的模糊 TODO 不得长期保留。
- 新增或移动重要模块、场景、定义资源和设计文档时，同步更新 `Doc/Index.md`；若索引尚未建立，应在项目进入正式开发结构时创建。
- 文档中的接口、路径与实际代码不一致视为缺陷。

```gdscript
## 根据 Haldane 映射函数计算两个位点间的理论重组率。
## `distance_morgan` 必须大于等于 0；返回值范围为 [0, 0.5)。
func recombination_fraction(distance_morgan: float) -> float:
    return 0.5 * (1.0 - exp(-2.0 * distance_morgan))
```

## 15. 版本控制与资源管理

- 使用 `.gitignore` 排除 `.godot/`、导出产物、编辑器缓存、临时存档与本机配置，并使用 `.gitattributes` 统一文本文件的 LF 换行。
- 提交 `project.godot`、导入源文件及其必要的 `.import`/UID 元数据；仅在确实不应被 Godot 导入和导出的目录中放置 `.gdignore`。
- 大型二进制美术和音频资源使用团队选定的 LFS/资产流程，不反复提交无意义的重编码文件。
- 移动 Godot 资源时优先在编辑器内操作，并检查 `.tscn`、`.tres`、脚本和 UID 引用是否完整。
- 每个提交聚焦一个可说明的改动；格式化、资源批量重导入与逻辑修改尽量分开。
- 禁止提交密钥、令牌、个人绝对路径、真实用户存档和包含隐私的日志。
